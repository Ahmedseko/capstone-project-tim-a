Judul Capstone:
"Perancangan dan Implementasi Sistem Informasi Manajemen Penjualan
dan Stok Berbasis Web pada UMKM Parfum Global Parfum Kutoarjo
Menggunakan Metode Waterfall"

Deskripsi Singkat:
Sistem Informasi Manajemen Penjualan dan Stok untuk UMKM Parfum —
aplikasi web untuk mengelola produk (harga & stok), transaksi
penjualan (kasir racik parfum per ml), struk, closing harian dengan
rekonsiliasi kas dan stok, laporan usaha termasuk laba, toko online untuk
konsumen (katalog, keranjang, checkout, cek pesanan) dengan pengelolaan
pesanan online oleh admin/staf, serta manajemen pengguna, secara terpusat
dan real-time menggantikan pencatatan manual.

2. LATAR BELAKANG & TUJUAN
====================================================================

Latar Belakang:
- UMKM parfum umumnya masih mencatat stok dan penjualan secara
  manual (buku/spreadsheet terpisah), sehingga rawan salah hitung
  stok, sulit rekap laporan harian, dan sulit dipantau real-time
  oleh pemilik usaha.
- Model jual toko parfum berbeda dengan toko biasa: parfum dijual
  per mililiter (contoh: Baccarat Rp4.000 per ml) lalu dimasukkan
  ke botol yang dipilih pembeli. Harga akhir = harga isi (ml x harga
  per ml) + harga botol. Ukuran botol bervariasi dan harga tiap
  ukuran botol berbeda. Pencatatan manual sulit menghitung ini dan
  sulit melacak stok parfum (dalam ml) dan stok botol (dalam buah)
  secara bersamaan.
- Pemilik juga perlu tahu laba dan kecocokan uang kas di akhir hari,
  bukan hanya omzet.

Tujuan Sistem:
1. Mendigitalkan pencatatan produk, stok, dan transaksi penjualan.
2. Mendukung penjualan racik parfum per ml + botol, di samping produk
   per buah (bibit, produk pendukung), dalam satu sistem.
3. Menjadikan Produk satu-satunya sumber data harga dan stok yang
   diatur admin, sehingga tidak ada input ganda dan harga konsisten
   di kasir, pesanan online, dan etalase.
4. Menyediakan mekanisme rekonsiliasi harian (closing): stok sistem
   vs stok fisik, dan uang tunai seharusnya vs uang di laci.
5. Menyediakan laporan penjualan dan laba (termasuk ekspor Excel)
   sebagai dasar pengambilan keputusan pemilik usaha.
6. Membedakan hak akses antara pemilik/admin dan staf toko.

3. METODE PENGEMBANGAN: WATERFALL
====================================================================

Waterfall adalah model pengembangan perangkat lunak yang berjalan
berurutan: setiap tahap diselesaikan dan menghasilkan dokumen/artefak
sebelum tahap berikutnya dimulai.

Tahapan dan hasil nyata pada proyek ini:

1. Analisis Kebutuhan (Requirements Analysis)
   - Mengidentifikasi proses bisnis toko parfum: produk, stok,
     penjualan, closing harian, laporan.
   - Menentukan pengguna dan hak akses: pemilik/admin dan staf toko.
   - Menetapkan kebutuhan khusus toko parfum: penjualan per mililiter
     (ml) yang dikemas ke botol pilihan pembeli, harga botol berbeda
     tiap ukuran, dan daftar varian parfum.
   - Hasil: daftar kebutuhan fungsional (modul dan fitur) dan peran
     pengguna.

2. Perancangan Sistem (System Design)
   - Perancangan antarmuka: desain layar (mockup) dan gaya visual.
   - Perancangan arsitektur: client-server dengan REST API
     (React, Express, MySQL).
   - Perancangan database: struktur tabel dan relasi
     (database/schema.sql).
   - Perancangan keamanan: autentikasi JWT dan pembatasan akses per
     peran.
   - Hasil: desain antarmuka, skema database, daftar endpoint API.

3. Implementasi (Coding)
   - Pembuatan kode frontend (React + TypeScript + Tailwind) dan
     backend (Node.js + Express), dikerjakan per modul: autentikasi,
     produk, stok, penjualan, closing harian, laporan, pengguna.
   - Hasil: aplikasi web yang dapat dijalankan (repositori GitHub).

4. Pengujian (Testing)
   - Pengujian fungsional setiap modul langsung di aplikasi.
   - Pengujian skenario terhadap MySQL asli (lihat bagian 11).
   - Pengujian instalasi dari nol memakai schema dan seed.
   - Hasil: temuan dan perbaikan bug sebelum penerapan.

5. Penerapan dan Pemeliharaan (Deployment & Maintenance)
   - Penerapan ke server (VPS) dengan Nginx dan layanan systemd.
   - Perubahan struktur database diterapkan lewat file migrasi
     bernomor, selalu didahului backup.
   - Permintaan perubahan setelah aplikasi dicoba pemilik/tim
     ditangani pada tahap ini sebagai perubahan terkontrol
     (change request), contohnya:
     * Model harga per ml + harga botol (Racik Parfum) dan Katalog
       Harga.
     * Ukuran botol dibatasi kelipatan 5 ml (5-100 ml).
     * Perombakan halaman Penjualan: diskon, uang diterima, struk
       cetak/PDF, pembatalan transaksi.
     * Harga modal dan laba, serta rekonsiliasi kas harian.
     * Perbaikan dari hasil uji coba (judul halaman, label
       pembatalan, logout otomatis saat sesi habis, batas stok ml,
       grafik).
     * Toko online untuk konsumen: halaman publik (profil toko, foto,
       lokasi dan Google Maps, katalog, keranjang, checkout ambil di
       toko/dikirim, cek pesanan), pesanan online yang masuk ke menu
       admin/staf, foto produk, dan penyesuaian stok (stok berkurang
       saat pesanan dikonfirmasi).
     Setiap perubahan melalui ulang analisis singkat, perancangan,
     implementasi, dan pengujian sebelum diterapkan.

Alasan memilih Waterfall:
- Ruang lingkup sistem informasi toko relatif jelas dan terstruktur
  (produk, stok, penjualan, closing, laporan).
- Setiap tahap menghasilkan dokumentasi yang mudah ditelusuri dan
  dinilai (kebutuhan, desain, kode, hasil uji).
- Cocok untuk proyek dengan tim kecil dan jadwal yang tetap.

Keterbatasan yang ditemui (bahan untuk slide "Evaluasi"):
- Kebutuhan toko yang berubah setelah aplikasi dicoba, terutama model
  harga per ml, baru jelas pada tahap penerapan sehingga memerlukan
  perubahan struktur database dan beberapa halaman. Pada Waterfall
  perubahan di tahap akhir lebih mahal dibanding perubahan di tahap
  awal. Pelajaran: libatkan pemilik toko lebih awal saat analisis
  kebutuhan, terutama untuk model harga dan cara jual.

5. ARSITEKTUR SISTEM
====================================================================

Pola Arsitektur : Client-Server, dengan REST API sebagai penghubung

    [ Browser ]
        |
        |  React SPA (dev: port 5173; produksi: file statis di Nginx)
        v
    [ REST API ]
        |
        |  Express.js (server, port 4000)
        |  Endpoint: /api/auth, /api/products, /api/catalog,
        |            /api/stock, /api/sales (+ /:id/cancel),
        |            /api/closing, /api/reports,
        |            /api/settings (+ /store), /api/users,
        |            /api/orders (pesanan online), /api/media (foto),
        |            /api/public (toko, katalog, foto, pesan, cek)
        v
    [ Database ]
        |
        |  MySQL 8.0
        v
    (users, price_catalog, media, products, stock_movements, sales,
     sale_items, daily_closings, daily_closing_items, settings,
     online_orders, online_order_lines)

Alur Autentikasi:
1. User login (email + password) -> backend verifikasi ke tabel users
   (password dicocokkan dengan bcrypt).
2. Backend menerbitkan JWT (masa berlaku 12 jam) berisi id, nama,
   email, dan role user.
3. Token disimpan di browser (localStorage jika "Ingat saya" dicentang,
   atau sessionStorage jika tidak).
4. Setiap request ke API menyertakan token lewat header
   "Authorization: Bearer <token>".
5. Middleware backend (requireAuth) memvalidasi token di setiap
   endpoint terproteksi; middleware requireRole('admin') membatasi
   endpoint tertentu hanya untuk admin.
6. Jika token kedaluwarsa, aplikasi otomatis keluar ke halaman login
   dengan pesan "Sesi Anda berakhir. Silakan masuk lagi."

Struktur Folder Proyek:
  client/              -> Frontend React + Vite + TypeScript + Tailwind
  server/              -> Backend REST API (Node.js + Express)
  database/            -> schema.sql (struktur tabel), seed.sql (akun
                          login + data contoh), migrations/ (migrasi
                          untuk database yang sudah berjalan)

Alur Data Penting (contoh: satu penjualan racik parfum):
  Kasir memilih varian + botol + isi (ml) -> keranjang -> server
  mengunci baris produk, memeriksa stok (jumlah produk yang sama
  digabung dulu), menghitung diskon & total, menyimpan transaksi dan
  item (termasuk salinan harga dan modal saat itu), mengurangi stok,
  dan mencatat pergerakan stok, semuanya dalam satu transaksi database.

7. FITUR UTAMA PER MODUL
====================================================================

A. LOGIN & AUTENTIKASI
   - Login dengan email & password.
   - Opsi "Ingat saya" (sesi tetap tersimpan setelah browser ditutup).
   - Validasi akun nonaktif ditolak login.
   - Logout otomatis dengan pesan jelas saat sesi kedaluwarsa.

B. DASHBOARD
   - Ringkasan penjualan hari ini (jumlah transaksi, pendapatan,
     item terjual). Transaksi yang dibatalkan tidak dihitung.
   - Laba hari ini (khusus admin).
   - Jumlah produk dengan stok menipis.
   - Grafik batang penjualan bulan berjalan (Recharts).
   - Daftar produk terlaris (diurutkan berdasarkan pendapatan).
   - Aktivitas/transaksi penjualan terbaru.
   - Daftar produk dengan stok menipis.

C. MANAJEMEN PRODUK (Produk)
   - CRUD produk: nama, kategori, ukuran, SATUAN JUAL (botol/pcs atau
     ml), harga, harga modal (admin), batas stok menipis.
   - Dua jenis produk utama untuk racik parfum:
     * Varian parfum (kategori Parfum Refill, satuan ml): harga per ml,
       stok dalam ml.
     * Botol kosong (kategori Botol Kosong, satuan pcs): harga tiap
       ukuran botol, stok dalam buah. Ukuran botol dipilih dari
       daftar kelipatan 5 ml (5-100 ml).
   - Kategori lain (bibit parfum, produk pendukung, parfum botolan)
     tetap dipakai sebagai pilihan.
   - Satu form lengkap: foto, nama, kategori, ukuran, satuan, harga
     jual, harga modal, STOK AWAL, batas stok menipis, deskripsi,
     tampil di etalase, status. Stok awal otomatis tercatat di riwayat
     stok (jenis masuk, "Stok awal produk").
   - Label harga/stok menyesuaikan satuan (per ml atau per botol).
   - Aktifkan/nonaktifkan produk langsung dari daftar.
   - Batas stok menipis default menyesuaikan satuan (100 ml untuk
     varian, 10 pcs untuk botol).
   - Filter berdasarkan kategori & status; pencarian produk.
   - Hapus produk: hapus permanen jika belum ada riwayat; otomatis
     dinonaktifkan jika sudah pernah dipakai di transaksi/stok.

D. KATALOG HARGA (DIHENTIKAN DARI ANTARMUKA)
   - Dulu daftar harga acuan terpisah; kini harga diatur langsung di
     Produk. Menu dan halamannya disembunyikan. Tabel price_catalog
     dan kolom products.catalog_id sementara dipertahankan (tidak
     dipakai) agar data lama aman; akan dibuang lewat migrasi nanti.

E. MANAJEMEN STOK (Stok)
   - Tabel stok saat ini per produk (satuan botol/pcs atau ml).
   - Koreksi stok langsung di baris: Edit -> isi stok aktual -> Save/
     Batal. Stok dikurangi wajib beralasan; dinaikkan boleh tanpa
     catatan. Dicatat sebagai penyesuaian (sebelum, sesudah, selisih,
     user, waktu, catatan). Riwayat tidak bisa dihapus; koreksi salah
     diperbaiki dengan koreksi baru.
   - Stok Masuk Massal: catat barang masuk untuk BANYAK produk sekaligus.
   - Closing Harian ikut menghitung penyesuaian manual sehingga stok
     awal tetap benar.
   - Riwayat pergerakan stok: stok masuk, penjualan, pembatalan,
     dan penyesuaian (dari closing harian), dengan stok sebelum &
     sesudah.
   - Tanggal stok masuk bisa diatur mundur (backdate).

F. PENJUALAN (Kasir / Point of Sale)
   - Tab "Racik Parfum":
     * Pilih varian dari kartu (nama, harga per ml, stok ml) dengan
       kolom cari.
     * Pilih ukuran botol dari tombol (ukuran, harga, stok).
     * Isi botol: tombol cepat Penuh / 3/4 / 1/2 / 1/4 atau input
       manual; isi tidak boleh melebihi ukuran botol maupun sisa stok.
     * Ringkasan hitungan langsung (contoh: 25 ml x Rp4.000 + botol
       Rp5.500 = Rp105.500).
   - Tab "Produk Lain": produk per buah (bibit, pendukung, dll).
   - Keranjang: satu racikan tampil sebagai satu item; isi (ml) dan
     jumlah botol bisa diubah langsung, dibatasi stok.
   - Diskon (Rp atau persen) dan catatan/nama pembeli (opsional).
   - Metode pembayaran: tunai, QRIS, transfer. Untuk tunai: uang
     diterima, tombol nominal cepat, dan kembalian otomatis.
   - Nomor transaksi otomatis dengan format TRX-YYYYMMDD-NNN.
   - STRUK: tampil setelah simpan; dapat dicetak ke printer apa pun
     (termasuk printer thermal 80 mm) atau disimpan sebagai PDF
     lewat dialog cetak browser.
   - Daftar "Transaksi Hari Ini" dengan tombol Detail (membuka struk
     dan cetak ulang).
   - PEMBATALAN TRANSAKSI (admin): wajib mengisi alasan; stok
     dikembalikan, transaksi ditandai Batal dan keluar dari laporan,
     dashboard, closing, dan ekspor Excel. Tidak bisa dibatalkan jika
     hari tersebut sudah di-closing.
   - Stok berkurang otomatis saat transaksi disimpan (transaksional,
     tervalidasi agar stok tidak bisa minus).

G. CLOSING HARIAN
   - Rekonsiliasi STOK sistem vs fisik per produk: stok awal, stok
     masuk, terjual, stok sistem, stok aktual (hasil hitung), selisih.
     Selisih otomatis dicatat sebagai penyesuaian stok.
   - Rekonsiliasi KAS:
     * Penjualan hari itu dipisah per metode bayar (tunai, QRIS,
       transfer).
     * Uang tunai seharusnya di laci = modal awal laci + penjualan
       tunai. Admin/staf mengisi modal awal dan uang hasil hitung;
       sistem menampilkan selisih kas (sesuai / lebih / kurang).
     * Hasil rekonsiliasi kas tersimpan saat hari ditutup.
   - Closing yang sudah difinalisasi terkunci (tidak bisa closing
     dua kali di tanggal yang sama).
   - Ringkasan otomatis: total transaksi, total item terjual (buah),
     total pendapatan hari itu. Transaksi batal tidak dihitung.

H. LAPORAN (Admin saja)
   - Laporan penjualan dengan filter rentang tanggal.
   - Kartu ringkasan: total transaksi, pendapatan, produk terjual,
     LABA KOTOR.
   - Laba kotor = total bayar (setelah diskon) dikurangi modal. Modal
     disalin ke tiap transaksi saat terjadi, jadi laba lama tidak
     berubah ketika modal berganti. Transaksi yang modalnya belum
     diisi tidak dihitung labanya; jumlahnya ditampilkan terpisah.
   - Grafik tren penjualan dan produk terlaris.
   - Tabel transaksi dengan kolom laba per transaksi.
   - Ekspor laporan ke Excel (.xlsx); laporan siap cetak.

I. TOKO ONLINE UNTUK KONSUMEN (halaman publik, tanpa login)
   - Beranda: nama dan profil toko, foto toko, jam operasional, alamat,
     nomor WhatsApp, email, tombol "Chat WhatsApp", kartu "Kunjungi
     Toko" dengan tombol "Buka Google Maps" dan pratinjau peta, serta
     tautan ke Shopee (jika diisi admin).
   - Katalog: foto, nama, jenis, ukuran, harga, status tersedia/habis,
     pencarian, filter kategori, urutan harga, tombol lihat detail dan
     tambah ke keranjang.
   - Detail produk: untuk parfum racik pelanggan memilih ukuran botol
     dan isi (ml) dengan harga yang terhitung langsung; produk jadi
     cukup memilih jumlah.
   - Keranjang disimpan di browser (tanpa akun); harga selalu diambil
     dari katalog terbaru.
   - Checkout: nama, nomor WhatsApp, catatan, dan metode "ambil di
     toko" (menampilkan alamat dan tombol Google Maps) atau "dikirim"
     (alamat wajib diisi).
   - Cek Pesanan: nomor pesanan + nomor WhatsApp -> status terbaru,
     tahapan, produk, total, dan metode.
   - Harga, ketersediaan, dan total selalu dihitung ulang di server;
     data yang dikirim browser hanya pilihan pelanggan.

J. PESANAN ONLINE (Admin & Staff)
   - Daftar pesanan dengan filter status dan pencarian, lencana jumlah
     pesanan baru di menu, dan penyegaran otomatis.
   - Detail pesanan: data pelanggan, alamat/metode, catatan, item, total,
     dan tombol "Hubungi via WhatsApp" yang membuka pesan otomatis:
     "Halo Kak [Nama], pesanan [Nomor] dari Global Parfum Kutoarjo sudah
     kami terima. Kami ingin mengonfirmasi pesanan Kakak."
   - Status: Baru -> Dikonfirmasi -> Diproses -> Siap Diambil/Dikirim ->
     Selesai; tambahan status Batal (dengan alasan).
   - Stok TIDAK berkurang saat pesanan masuk. Stok berkurang saat admin/
     staf menekan "Konfirmasi Pesanan" (pesanan dicatat sebagai penjualan
     dengan harga saat pelanggan memesan, sehingga laporan, closing, dan
     laba ikut). Jika dibatalkan setelah dikonfirmasi, stok dikembalikan
     otomatis.
   - Ringkasan di dashboard: pesanan baru, sedang diproses, selesai,
     penjualan hari ini dan bulan ini, produk terlaris, stok menipis.

K. PENGATURAN & MANAJEMEN PENGGUNA (Admin saja)
   - Identitas toko: nama toko, pemilik, alamat, telepon/WhatsApp,
     email, link Google Maps, link Shopee, jam operasional, profil
     singkat, mata uang, ambang batas stok menipis default. Dipakai pada
     struk dan halaman toko online.
   - Foto toko (hingga 12) dan foto/deskripsi produk; produk dapat
     disembunyikan dari toko online.
   - Manajemen pengguna: tambah user baru, ubah role (admin/staff),
     aktifkan/nonaktifkan akun.
   - Admin tidak bisa menonaktifkan akunnya sendiri.

9. STRUKTUR DATABASE (12 TABEL)
====================================================================

1. users
   id, name, email (unik), password_hash, role (admin/staff),
   is_active, created_at, updated_at

2. price_catalog  (daftar harga acuan, diisi admin)
   id, name (unik), category, size, unit (botol/ml), price,
   cost_price, created_at, updated_at

3. products
   id, catalog_id (FK->price_catalog, boleh kosong), name, category,
   size, unit (botol/ml), price, cost_price, stock, low_stock_threshold,
   status (aktif/nonaktif), created_at, updated_at
   (stok varian dalam ml, stok botol dan produk lain dalam buah)

4. stock_movements  (riwayat pergerakan stok)
   id, product_id (FK->products), type (masuk/penjualan/penyesuaian),
   quantity, stock_before, stock_after, note, user_id (FK->users),
   created_at
   (pembatalan transaksi dicatat sebagai pergerakan "penjualan"
   bernilai positif dengan catatan "Pembatalan TRX-...")

5. sales  (transaksi penjualan)
   id, transaction_number (unik), date, total (setelah diskon),
   discount, payment_method (tunai/qris/transfer), customer_note,
   amount_paid, status (selesai/batal), cancel_reason, cancelled_at,
   cancelled_by (FK->users), user_id (FK->users), created_at

6. sale_items  (item per transaksi)
   id, sale_id (FK->sales), product_id (FK->products), quantity,
   unit_price, cost_price (salinan modal saat transaksi, boleh kosong),
   subtotal
   (satu racikan tersimpan sebagai dua item: varian [quantity = ml]
   dan botol [quantity = buah])

7. daily_closings  (rekap closing harian)
   id, closing_date (unik), total_transactions, total_items_sold,
   total_revenue, total_cash, total_qris, total_transfer,
   opening_cash, cash_actual, cash_difference, status
   (terbuka/ditutup), note, closed_by (FK->users), created_at

8. daily_closing_items  (detail rekonsiliasi stok per produk)
   id, closing_id (FK->daily_closings), product_id (FK->products),
   opening_stock, stock_added, quantity_sold, system_stock,
   actual_stock, difference, note

9. settings  (identitas & konfigurasi toko)
   id, store_name, owner_name, address, phone, currency,
   default_low_stock_threshold, email, maps_url, opening_hours,
   store_profile, shopee_url

10. media  (foto produk dan foto toko, disimpan sebagai BLOB)
   id, kind (produk/toko), mime, size, data, sort_order, created_by

11. online_orders  (pesanan konsumen)
   id, order_number (unik, ORD-YYYYMMDD-NNN), customer_name,
   customer_phone, fulfillment (ambil/kirim), address, note, total,
   status (baru/dikonfirmasi/diproses/siap/selesai/batal),
   sale_id (FK->sales, terisi saat dikonfirmasi), cancel_reason,
   confirmed_by, confirmed_at, created_at

12. online_order_lines  (baris pesanan seperti yang dilihat pelanggan)
   id, order_id (FK->online_orders), kind (racik/produk), label,
   detail, quantity, unit_total, subtotal, components (JSON bahan stok
   per unit: produk, jumlah, harga saat memesan)

Tabel products juga memiliki photo_id (FK->media), description, dan
show_online (tampil/tidak di toko online).

Relasi utama: online_orders <-1:N- online_order_lines, online_orders
-N:1-> sales (saat dikonfirmasi), media <-1:N- products (foto),
price_catalog <-1:N- products, products <-1:N-
stock_movements, products <-1:N- sale_items, sales <-1:N- sale_items,
daily_closings <-1:N- daily_closing_items, users <-1:N-
stock_movements/sales/daily_closings (siapa yang input/membatalkan).

Prinsip desain: harga dan modal disalin ke tiap transaksi (snapshot),
sehingga mengubah harga di masa depan tidak mengubah laporan masa lalu.

10. KEAMANAN & KEANDALAN SISTEM
====================================================================

- Autentikasi berbasis JWT, masa berlaku token 12 jam.
- Password di-hash dengan bcrypt (10 salt rounds) — password asli
  tidak pernah disimpan.
- Middleware requireAuth memverifikasi token di setiap endpoint API
  yang butuh login; requireRole('admin') membatasi endpoint sensitif
  (produk create/update/delete, katalog, pembatalan transaksi,
  laporan, ekspor Excel, pengaturan, manajemen pengguna).
- Data sensitif dibatasi di sisi server: modal dan laba hanya
  dikirim untuk admin.
- Validasi input di backend (service), bukan hanya di frontend:
  harga, diskon (tidak boleh melebihi subtotal), uang diterima,
  metode pembayaran, ukuran botol (kelipatan 5 ml, 5-100 ml).
- Transaksi database (DB transaction + row locking) pada penjualan,
  pembatalan, dan closing; jumlah produk yang sama dalam satu
  transaksi digabung sebelum cek stok, sehingga stok tidak bisa minus
  atau tercatat ganda saat diakses bersamaan.
- Pembatalan transaksi tidak diizinkan setelah hari tersebut
  di-closing, dan tidak bisa dilakukan dua kali.
- Rahasia (kata sandi database, kunci JWT) disimpan di file .env yang
  tidak ikut ke repositori; hanya .env.example yang disertakan. Rahasia
  produksi diputar sebelum aplikasi dipublikasikan, dan server menolak
  start dengan kunci JWT bawaan saat NODE_ENV=production.
- Lapisan jaringan: HTTPS dengan HSTS, Content-Security-Policy, dan header
  keamanan lain; HTTP dialihkan ke HTTPS; pembatasan percobaan login (10
  per menit per IP); permintaan ber-Content-Encoding ditolak; port backend
  tidak terbuka ke internet; CORS hanya untuk origin yang dikonfigurasi.
- Prinsip hak minimum: akun database aplikasi hanya boleh membaca dan
  menulis data (tidak boleh mengubah struktur tabel); layanan backend
  berjalan dengan sandbox sistem (tanpa hak istimewa, tanpa akses jaringan
  selain loopback).
- Dependensi dan runtime dijaga mutakhir terhadap kerentanan yang diketahui
  (Node.js dan body-parser ditambal sebelum aplikasi dipublikasikan).
- Keamanan halaman publik (tanpa login): katalog publik hanya memuat
  data aman (tanpa modal dan tanpa angka stok); pesanan divalidasi
  penuh di server (harga, stok, ukuran, jumlah dihitung ulang, input
  dari browser tidak dipercaya); pembatasan laju di Nginx dan per nomor
  WhatsApp; kolom jebakan untuk bot; cek pesanan wajib nomor pesanan
  DAN nomor WhatsApp yang cocok, dengan jawaban sama untuk salah satu
  yang keliru; alamat dan nomor pelanggan tidak dikembalikan oleh
  endpoint publik; tautan (Maps, Shopee) harus https; foto dicek dari
  isinya dan tidak boleh SVG; Content-Security-Policy hanya mengizinkan
  peta Google sebagai bingkai tertanam.
- Konsistensi stok pesanan online: konfirmasi dan pembatalan berjalan
  dalam satu transaksi database bersama mesin penjualan, dengan harga
  saat pelanggan memesan; konfirmasi gagal utuh (tanpa mengubah apa pun)
  kalau stok tidak cukup.
- Perubahan struktur database di server produksi selalu didahului
  backup (mysqldump).

13. CARA MENJALANKAN APLIKASI (RINGKAS)
====================================================================

1. Nyalakan database   : docker compose up -d
2. Nyalakan backend    : cd server && cp .env.example .env
                          && npm install && npm run dev
                          -> berjalan di http://localhost:4000
3. Nyalakan frontend   : cd client && npm install && npm run dev
                          -> berjalan di http://localhost:5173
4. Buka browser ke http://localhost:5173 dan login.

Alur mencoba cepat: Login (admin) -> Produk (tambah produk + stok
awal) -> Stok (edit stok) -> Penjualan > Racik Parfum -> simpan -> struk ->
batalkan transaksi -> Closing Harian (stok & kas) -> Laporan (laba).
